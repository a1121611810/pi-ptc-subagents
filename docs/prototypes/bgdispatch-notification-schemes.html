方法论

4 方案每档位字节估算

// Constants
META_BYTES          = 200  // XML/JSON overhead per notification (taskId, status, label, durationMs, etc.)
REF_STRING_BYTES    = 100  // file path string for outputRef
INLINE_THRESHOLD_A  = 8*1024  // tiered inline cutoff
PREVIEW_THRESHOLD_BC = 2*1024  // reference / map-preview inline preview cutoff
PREVIEW_TAIL_A      = 4*1024  // tiered medium-case preview tail bytes
MEDIUM_THRESHOLD_A  = 50*1024 // tiered medium cutoff

// A. TIERED (8KB inline / 4KB tail / pointer only)
if   (sz <= 8KB)   bytes = sz + META                          // inline full
elif (sz <= 50KB)  bytes = 4KB + META + REF                   // 4KB tail + ref
else               bytes = META + REF                          // pointer only
RT (model decides if preview insufficient):
  ≤8KB → 0 RT (full inline)
  8-50KB → 1 RT (4KB tail usually insufficient for action)
  >50KB → 1 RT (no inline)

// B. REFERENCE (always ref + optional ≤2KB preview)
bytes = META + REF                                            // always ref
if (sz <= 2KB) bytes += sz                                    // preview = full since ≤2KB
RT: ≤2KB → 0 RT, >2KB → 1 RT

// C. MAP + SMART PREVIEW (no ref + optional ≤2KB preview)
bytes = META                                                  // no ref, registry is source
if (sz <= 2KB) bytes += sz                                    // preview = full since ≤2KB
RT: ≤2KB → 0 RT, >2KB → 1 RT

// D. STRICT MAP (no ref + no preview ever)
bytes = META                                                  // metadata only
RT: 1 RT every task

Token 估算

1 token ≈ 4 chars (English/JSON/XML)。200K 上下文窗口 = 800 KB raw bytes。占窗% = (bytes / 4) / 200000 * 100。

Round-trip 延迟

默认 250 ms/turn 模拟 LLM tool call 决策（pi/Claude 经验值）；可调。deref 走 ptc_task_output(taskId)。

为什么 reference 体积用字节而不是字符

JSON / XML / path 字符串 ASCII 主导，4 char ≈ 1 token 是合理近似。中文输出 60% token 效率会下降，但不影响**方案间相对差距**——所有方案按相同规则吃亏。
