entry 装配

packages/entry
F9Nice任务面可见性会撤掉用户自己固定的工具
packages/entry/src/index.ts:267-274
这是什么
before_agent_start 和每次 registry 变迁时跑 applyTaskFaceVisibility：有记录就加三个任务面工具，没有就滤掉。
问题
用户在 loadout 里自己固定了 ptc_task_list，而新会话还没有任务记录时，滤掉分支会把用户自己开的工具从活跃表移除。
修复
只滤「本会话自己加的」——维护一个小集合，或滤前判断非用户 loadout 项。
不修的后果
用户偶尔困惑「工具怎么没了」，重开即可，无数据损失。

worker 池 + 程序执行

packages/ptc · dispatcher/pool/worker-main
F7NicerenderModelValue 不限制子项数
packages/tui/src/text.ts:38-57
这是什么
程序返回值排版成可读文本给模型，是 worker 结果回宿主后的渲染步。
问题
只有深度上限 4 层，没有契约里写的每层 6 个子项上限。返回 10 万元素数组 → 先渲染几十 MB 字符串，再被下游截断砍掉，白干 99%。
修复
循环里数子项，超出加「…（余 N 项）」，五行。
不修的后果
极端返回值时一次工具调用慢几百毫秒，结果一样。
F8Nice池化 worker 每次 run 挂 3 个监听器、从不摘除
packages/ptc/src/dispatcher.ts:105-217
这是什么
runPtcProgram 给 worker 挂 message/error/exit，run 结束只 reset 不复位监听。
问题
entry 每个 turn_end 都 drain 池（index.ts:236），worker 活不过一个 turn——所以只是单 turn 内累积：一个 turn 跑几十次程序时每个 worker 挂上百个闭包。
修复
finish 时 removeAllListeners 或改一次性 handler。
不修的后果
单 turn 内内存缓慢上涨，turn 边界清零。可忍。

任务门

packages/ptc · task-binding.ts
F1Must fix任务门声明 cwd 参数，两个入口都静默丢弃
packages/ptc/src/task-binding.ts:14（schema）· packages/entry/src/index.ts:516（丢弃）
这是什么
pi_task_ptc 与 pi_task_codemode 共用 TASK_DOOR_PARAMETERS，里面有 cwd——「孩子的工作目录」。
问题
绑定层转发时没有 cwd 字段；DispatchInput、六道闸、引擎、createTask 全链都没有 cwd。模型传了 cwd 拿到成功返回，孩子却在父目录跑。
修复
最小修复：从 schema 删掉 cwd；或者真接到 buildPiArgv。倾向先删。
不修的后果
模型越来越信任这个参数，孩子在错误目录读写文件。

⑥ 环节

dispatch 引擎

packages/dispatch
F2Should子进程 stdout 无上限累积（stderr 有 64KB 帽）
packages/dispatch/src/engine.ts:329-331 · 对比 child-process.ts:5
这是什么
引擎把孩子的全部 stdout 收进一个内存字符串，收完才落盘、才解析。
问题
stderr 有 64KB 尾部上限，stdout 没有。json 模式下整段会话流都在 stdout——一个刷输出的孩子就能撑爆宿主内存。单用户负载也成立。
修复
照 stderr 的样子给 stdout 加 8–16MB 尾部上限，超限在记录里标 outputTruncated。
不修的后果
一个失控孩子拖垮整个宿主会话。
F3Should任务记录与产出只增不减
packages/dispatch/src/engine.ts:473-483 · packages/entry/src/index.ts:144
这是什么
每个任务一条 TaskRecord（内存 Map + .pi/ptc-tasks/records/*.json）加一份 output.log。
问题
终态记录永驻内存；磁盘文件跨会话永久保留。会话开几周后 list() 要 sort 全部终态记录，项目目录里持续积垃圾。
修复
内存侧淘汰最老终态（如超 200 条）；磁盘侧会话启动时清掉/归档上次会话的终态文件。
不修的后果
变慢 + 用户项目目录无界膨胀。
F4Should最危险的纯逻辑零自动化测试
registry.ts:4-12（状态机）· slots.ts（FIFO/提拔）· report.ts:42（报告抠取）
这是什么
状态转移表、槽位 release/cancelQueued 竞态、extractReportFromText 多代码块回溯——正确性支柱，全是纯逻辑。
问题
packages/ 下零测试文件，只有 docs/research 里的一次性探针。这三处改错只在真机上炸。
修复
测试框架（探针转正）落地时按此顺序各盖一个测试文件。
不修的后果
排查成本远高于测试成本。

子代理进程

pi child · --mode json
F5Should搜索记忆对「非搜索结果」的页面永远存不住
packages/search/src/memory.ts:49-59
这是什么
子代理进程内 web_ds_search 的 open 抓到正文后，经 storeText 存进记忆，find 命中则免费。
问题
storeText 只在「最近 5 次搜索的结果列表里有这个 URL」时才存。直接 open 模型已知的 URL → 正文被静默丢弃 → 随后 find 同一 URL 再抓一次、再烧一次配额。注释承诺兑现不了。
修复
记忆加一个独立 textByUrl 兜底桶（共用 400K 预算），存不进搜索条目时存那里。
不修的后果
配额在重复抓取上白烧，搜索上限更快撞墙。
