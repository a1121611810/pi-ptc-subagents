这一版修掉了上一版图里那个错误格子，并且补上了一个新的修复

上一版写错的地方：我写的「TUI + codemode 激活 ⇒ 模式进入」不成立。实测：decideModeEntry 的第三个条件是「模型面前有 ptc_run_code/ptc_workflow」，而 subagents 表面上这两个是 codemode reach ⇒ 不是 model-facing ⇒ 条件永不满足 ⇒ 报 tools-unavailable ⇒ 模式进不去。

补上的新修复：「怎么派子代理」现在写进系统提示词的一个 section（<ptc>），不再只挂在工具描述上。理由：pi 只从 declared 的工具收集 guidelines，而 codemode reach 的工具连 guidelines 都进不了模型上下文 ⇒ 上一版那个「父会话连摔三次 tools.pi.dispatch does not exist」的缺陷，根因不是模型没读，而是它无处可读。section 是 pi 无条件并进系统提示词的，所以这一句对每个表面都到得了。

实测效果：subagents 表面上，父会话从「写 codemode 脚本 → 三次 TypeError → 才退到 ptc_subagent」变成直接调 ptc_subagent，零次 TypeError。

全景：一条链，四个判定点

竖着读是时间顺序。四个判定点分别是：表面（注册什么）、模式（模型面前剩什么）、派单形状（怎么叫到孩子）、档位（孩子的工具白名单）。

八格全表：表面 × 运行模式

每格都是真机跑出来的。「收窄」指七个内建工具是否从模型面前消失；「父有 bash」决定父能不能绕过整个设计自己联网。

表面运行模式收窄父面前有什么父有 bash派单的路实测
full tui 进 ptc_run_code / ptc_workflow / ptc_task_* 没有 写程序 → 程序内 pi.dispatch 模式进入已实测
print / json / rpc 不进（not-tui） 一切照常 + 我们的工具 有 同上（父自己 curl 也行） DISPATCHED
subagents tui 不进（tools-unavailable） codemode / ptc_subagent / ptc_task_* ＋ 内建 有 直接调 ptc_subagent DISPATCHED
print / json / rpc 不进（not-tui） 同上 有 直接调 ptc_subagent DISPATCHED

**只有第一格**是「父不能自己联网」的形状。`subagents` 表面上 ptc_run_code 不是 model-facing ⇒ 收窄的前提不成立 ⇒ 模式进不去 ⇒ 父保留 bash。

这一轮真机测到了什么

subagents 面 · 修 section 之前

  • 父的第一反应：写 pi 的 codemode 脚本
  • 连摔三次：TypeError: tools.pi.dispatch does not exist
  • 退到 ptc_subagent，派单成功
  • 父自发加了 readOnly:"strict"
  • 孩子工具表 = read,grep,find,ls,ptc_child_report，没有搜索工具
  • 孩子自报「no web search, web fetch, or bash tool」并放弃
  • 父如实回报「我没拿到那页内容」

⇒ 能力不是被绕过的，是不存在，而且静悄悄。

subagents 面 · 修完

  • 父直接调 ptc_subagent，零次 TypeError
  • 孩子工具表带 web_ds_search（strict 也保留）
  • 孩子调了十几次 web_ds_search 并自己找到那页（json 17 次、rpc 14 次）
  • 父拿到逐字原文
  • 四种运行模式（tui / print / json / rpc）全部 DISPATCHED
  • 第一次 rpc 测量其实是无效的：脚本的进程代理把 stdin 设成了 ignore，提示词压根没送到父会话，于是报出「父什么也没调」——看着像模型拒绝派单，其实是 harness 自己坏了。现在代理会转发 stdin，且脚本会区分「模型拒绝派单」与「根本没跑」

复现（四种模式各跑一遍）：PTC_E2E_SURFACE=subagents PTC_E2E_MODE=json node scripts/verify-parent-dispatch-e2e.ts；tui 需要 pty：script -q /dev/null env PTC_E2E_MODE=tui PTC_E2E_SURFACE=subagents node scripts/verify-parent-dispatch-e2e.ts
