# `/ptc off` 改成截断：两个表面各自的截断点

Status: accepted (2026-10-21). Ticket #242（spec #234 实现决定 7）。修订：[ADR-0004](./0004-ptc-off-stops-new-dispatch.md) 决定 1 与决定 3、[ADR-0006](./0006-the-two-doors-share-one-prefix.md) 决定 6。**本篇与这两篇读得不一样的地方，以本篇为准。**

> **Amended by [ADR-0013](./0013-route-registry.md) (2026-10-21): the shared sentence this record introduced (`PTC_TRUNCATED_NO_NEW_TASK`) moved into the route registry (`src/routes/registry.ts`) — one home for every piece of model-facing prose. The model's section and the user's notice still carry the same sentence, and the test still asserts both.**

## Context

ADR-0004 把 `/ptc off` 做成**一道闸**：门还留在模型面前，调用被拒。闸落在 `dispatch()` 里，两个面都经过它，所以「停收新的」这件事在两个面上都成立。

闸的问题不在「拒得对不对」，而在**它留着一扇门去拒绝**。模型面对着一扇它叫不动的门：它知道「不许」，不知道「没了」。而门其实是可以撤的——pi 撤不掉工具，但 pi 能**覆盖**它。

两个表面各有一件**撤不掉**的东西，而它们不是同一种：

- `full_ptc`：编排器是本包自己的 PTC。整层都是本包的，所以整层都能撤。
- `codemode_ptc`：编排器是 pi 的 `codemode`。**它不是本包的**，本包没法把它从模型面前拿走。

这一条差别就是本篇的全部：两个表面的截断点不同，只因为**撤不掉 pi 的 codemode**。

## Decision

**1. `/ptc off` 是截断，不是闸门。** 截断点落在**本包能控制的那一段**的起点：撤掉本包在链上的那一段，而不是留着它去拒绝。

**2. 撤一个工具的办法是同名重注册为 `hidden`。** pi 的 `registerTool` 是对工具名做 `Map.set`，所以同名再注册一次就是**替换**那条记录，而不是多一条。`exposure: "hidden"` 的工具既不在**声明给模型**的那一套里（pi 在算声明集时把 `hidden` 滤掉），也不在**`codemode` 脚本可调**的那一套里（可调集是每次访问现算的，它读的是当前的 exposure）。pi 自己的 MCP 扩展撤工具走的正是这条路，所以这不是 hack。

**3. 两个表面的截断点不同，理由只有一个。**

- `full_ptc`：**撤掉整个编排层**——`ptc_run_code` 与 `ptc_workflow` 一起撤。模型回到内置工具直调，没有编排器，也就没有「门」可言。建任务入口（`pi_task_ptc`）住在 PTC 程序里，**撤掉程序即不可达**，没有第二个注册要撤。
- `codemode_ptc`：`codemode` **继续编排**（它还能调内置工具、还能干别的），但它下面属于本包的那一段被撤掉——**执行层**（`ptc_run_code` 与 `ptc_workflow`）与**建任务入口**（`pi_task_codemode`）。

所以**建任务入口在两个表面上都撤得走**，只是手段不同：`codemode_ptc` 侧它是一个**注册的工具**，同名重注册为 `hidden` 就同时从声明集与可调表里消失；`full_ptc` 侧它住在程序里，撤掉程序即不可达。

**4. 撤掉之后，模型从下一个 turn 起才看不见它。** 这一条是实测的（pi 1.3.0 的源码）：

- **可调集每次访问现算。** pi 的 `AgentSession._getCallableTools()` 每次都从工具注册表过滤一遍，exposure 读的是**当前定义** → 同名重注册为 `hidden` **立刻**对可调集生效。
- **声明给模型的那一套每个模型请求重算。** pi 的 `_applyToolLoadout` 从 `setActiveTools` 与请求路径两处被调用 → 撤掉工具对**下一个模型请求**生效。

⇒ **在翻转开关的那一个 turn 里，模型已经发出的那个请求仍然带着旧的声明。** 那个窗口里的一次调用必须**被拒绝**，不能被静默放行。

**5. 闸不删，它是那个窗口的防线。** `dispatch()` 里那道 `dispatchEnabled` 闸保留为**纵深防御**：它不在调用路径上多花一次判断，它接住的是「模型还拿着旧声明就发了一次调用」这件事。这道闸归另一票所有，本篇不动它。

**6. `/ptc off` 的确定语义不变：停收新的 + 抽掉排队中的 + 在跑的照常。** 截断改的是「门在不在」，不是「已开始的那些怎么办」。排队中的那些被抽掉（ADR-0011），在跑的那些是独立进程，off 够不到它们——通告里明写「NOT affected」。

**7. 生命周期面跟着「有没有记录」走。** 已经有任务记录时，那三个任务工具仍在模型面前，仍然可查可停（ADR-0007）。截断撤的是**建任务**的那一段，不是**管任务**的那一段——后者是「在跑的照常」这半句能落地的前提。

**8. 开关是幂等的。** 反复开关不产生重复注册，也不留残留：撤销时重注册的是**原始定义**（曝光是这一面给它的那个），恢复时重注册的也是原始定义，所以没有一层 `hidden` 会留下来。

**9. 恢复的时机。** `/ptc on` 把这一段放回去（重新注册原始定义），并且**在写回 loadout 之后**——写 loadout 会替换活动集，而那一刻还处于撤销状态的工具会被直接滤掉。

**10. 恢复也走持久化。** 这条开关是会话级的（ADR-0004 决定 5），所以**续跑**一个带着「off」记录的会话时，那一段也是撤着的——续跑是同一个会话。

## 代价

- **一次同名重注册 + 一次注册表刷新。** pi 在重注册后重建定义表并重新应用活动集，代价与注册一个工具同量级。开关是一次性的、会话内很少发生的事件，这个量级可以接受。
- **模型在下一个 turn 才看见变化。** 这是 pi 的声明集重算时机决定的，不是本包的选择。它换来的是：翻转之后的那一个 turn 里没有「模型以为工具在、其实不在」的静默失败——那次调用被闸明确拒绝，而不是报一个「工具不存在」让模型去猜。
- **模型面多了一句话要维护。** 撤销状态下 `<ptc>` 段给的是「共享的那一句」+「这一面撤掉了什么」。共享的那一句（`PTC_TRUNCATED_NO_NEW_TASK`）同时被模型的段与用户的通告带着，所以两边不会各说各话。
- **两个表面各有一份「撤掉了什么」的文案。** 这是截断点不同的直接后果，不是一处文案的两次抄写：两个表面的事实本来就不同。

## 与其它记录的关系

- **[ADR-0004](./0004-ptc-off-stops-new-dispatch.md)**：这个开关归它管。它的决定 1（「停掉所有新的派发」）在**闸**这一层仍然成立且仍然需要——本篇把它降级为**纵深防御**（决定 5），而把 `/ptc off` 的主语换成**截断**（决定 1 与决定 3）。它的决定 3（露面条件）由 ADR-0007 与 ADR-0011 兑现，本篇沿用。
- **[ADR-0006](./0006-the-two-doors-share-one-prefix.md)**：决定 6 的共享搜索句现在多了一个面（模式简报），而它唯一的家是搜索模块自己的常量；本篇没有改那条决定，只把它落到三个面上。
- **[ADR-0011](./0011-cancellation-only-reaches-queued-tasks.md)**：`/ptc off` 的确定语义（停收新的 + 抽掉排队中的 + 在跑的照常）是它定的，本篇原样保留（决定 6）。
- **[ADR-0007](./0007-every-dispatch-is-a-task.md)**：生命周期面跟着记录走，所以撤销「建任务」这一段并不影响「管任务」那一段（决定 7）。
- **[ADR-0005](./0005-the-surface-names-the-orchestrator.md)**：表面值指的是**哪个编排器对模型负责**——本篇的截断点正是从那一句推出来的：`full_ptc` 的编排器是本包的，所以能撤；`codemode_ptc` 的编排器是 pi 的，所以不能。

## Reopen triggers

- **pi 提供了真正的注销**（而不是覆盖）——那撤工具就不必再靠「同名重注册为 `hidden`」这条路，本篇的决定 2 可以换掉。
- **pi 的 `codemode` 变成可撤的**（比如它自己提供了一个「关掉我」的开关）——那么两个表面的截断点可以合并成一个，本篇的形状整体简化。
- **要「关掉正在跑的」**——那是一个 kill 开关，不是这一条；`ptc_task_stop` 已经是那条路（ADR-0011）。
- **要跨会话生效**——现在是会话级（旧 ADR-0043 的 `why` 同一形状）。长期关掉整个包的现成做法是 `pi config` 停用本包，那连工具都不注册。
