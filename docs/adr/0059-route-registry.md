# 模型面散文只有一个出处：一个类型化的 route registry

Status: accepted (2026-10-21). Ticket #243（spec #234 实现决定 8 的散文那一半）。修订：[ADR-0022](./0022-background-dispatch.md)、[ADR-0024](./0024-binding-contract-declares-binding-result.md)、[ADR-0049](./0049-the-search-lives-in-the-child.md)、[ADR-0052](./0052-the-two-doors-share-one-prefix.md)、[ADR-0054](./0054-the-two-doors-give-one-object.md)、[ADR-0055](./0055-wait-is-one-parameter.md)、[ADR-0057](./0057-cancellation-only-reaches-queued-tasks.md)、[ADR-0058](./0058-ptc-off-truncates-the-chain.md)。**本篇与这八篇读得不一样的地方，以本篇为准。**

## Context

到 2026-10-21 为止，本包里有**八十七处**模型面散文，散在二十三个源文件里。散文本身没有问题——问题是**同一句话被写了两遍**，而两遍会漂。

清点稿（read-only，不在仓库里）逐条记下了每一处散文的位置、原文与分类，并找出**三处**已经在漂的重复：

1. **`agent` 可选那句**：两个 PTC 工具的描述里各写一遍（`run-code` 与 `workflow`）；
2. **「程序：一个 async TypeScript 函数体」**：两个参数 schema 里各写一遍（`code` 与 `script`）；
3. **`whySuppressed` 的 schema 描述**：两个 `outputSchema` 里各写一遍。

三处都是同一个形状：**同一个教训被抄了两遍**。第一处是两边各自补的修复，第二处是 schema 各自补的说明，第三处是投影与本体各自补的一句。抄完之后没人再回头比对，于是它们已经开始分叉——第三处那两句的尾巴本来就不一样。

还有一类是**已经修好的**：共享常量（reach note、web 那句、stop 那句、门那句）。它们是本仓一路在消灭的毛病里少数活下来的样本——**一个常量，两个表面引用它，一条测试断言两边都含那个常量本身**。本篇要做的，是把这条已经证明可行的做法，从「几处个案」变成「全包的规矩」。

## Decision

**1. 一个册子文件：`src/routes/registry.ts`。** 它是本包**全部**模型面散文唯一的出处，两个区：

- `TOOLS`——**一个工具一条**：它是什么（事实那一半）、片段（snippet）、指南（guidelines）。
- `ROUTES`——**一条路一行**：什么时候走它、每个表面上怎么调它、事实、详情文件的指针。**本票只建区与类型，路本身由 #246 填**（那一票还负责渲染常驻索引与随包详情文件）。

**2. 工具文件里不再有这些字的字面量。** 工具文件只留 schema 与行为；描述、指南、片段**从册子里渲染出来**。于是「同一句话写在两个地方」这件事在结构上不再可能——要写第二遍，就得再写一遍那个字面量。

**3. 描述是**有序**的段落列表，不是字符串。** 段落要么是册子自己的文字，要么是一个**槽位**（slot）：册子不拥有的散文放进去。两种槽位：

- **绑定契约**——它回答的是「调了得到什么形状」，与「什么时候调、调的是什么」不重叠，所以**它留在册子之外**（ADR-0024 的形状、它自己的 token 预算、它自己的双向测试都不动）。册子只决定**它放在哪一段**。
- **会话自己的话**——这个会话的孩子能不能搜网、这个会话的搜索有没有凭据、这个安装注册了哪些 agent。这些是**关于会话的事实**，不是关于工具的事实，所以由会话填进槽位，工具文件一个字都不提。

**4. 留在册子外面的东西，明写出来：** 参数 schema（连它的 description——spec 决定 10 的第 9 条：**参数与它的说明是一体的**，拆开反而更难读）；**renderer**（把活数据变成文本的东西，数据不是散文）；**会话注入里的动态绑定清单**（哪些绑定可用是关于会话的事实）；**绑定契约**。

**5. 共享句子的新家在册子里。** 三处重复各变成**一个共享常量**（册子里的 `AGENT_OPTIONAL_CLAUSE`、`PROGRAM_BODY_DESCRIPTION`、`WHY_SUPPRESSED_DESCRIPTION`），已有的那几句（reach note、web 那句、stop 那句、门那句、截断那两句）也一并搬进来。搬进去之后，原来那些模块**重新导出**它们，读者不用改 import，而**字面量只存在于册子里一份**。

**6. 「后台」这个模式退役后的说法。** ADR-0055 之后只有一条路加一个 `wait` 参数，所以模型面散文不再有「后台任务」与「前台任务」两种说法：**任务就是任务，等不等是一个参数**。渲染器那一侧的 `waited` / `not waited` 措辞由 #239 之后的另一次改动落地。

## 证据

1. **三处重复是真的，实测在册子里可查。** 每处都在两个表面上被找到，且**第三处已经分叉**（同一句话的尾巴在两个 `outputSchema` 里不一样）。清点稿把它们逐条记下了位置与原文。
2. **一处散落的散文会先变成两处，再变成三处。** 「选路知识」曾经同时住在四个通道里（自定义 section、会话内注入、rules 扁平日志、tool description），每一处都是踩过坑之后补的——同一个教训被抄了三遍，改一处就漏两处。这不是「有人不小心」，是**没有单一出处时必然的形状**。
3. **共享常量这条路已经走通过。** 本仓已经有五个「一句话、两个表面、一条测试断言两边都含它」的样本（reach note、web 那句、stop 那句、门那句、截断那一句）。本篇不是发明一个新机制，是**把已经成立的机制变成全包的规矩**。
4. **搬完之后，漂移在结构上不可能。** 册子的测试直接扫源码：册子里的每一段文字都**不许**出现在任何工具文件里（超过 40 个字符的段落与共享常量）。这不是「记得别复制」，是**复制了会红**。

## 代价

**册子成了每个写工具的人都要读的文件。** 这是本篇最实在的代价：新增一个工具的人，第一件事不是写 schema，是**在册子里给它立一条**，然后从那里渲染描述。绕过册子的人会撞上一条源码扫描的红。

这份代价换来的是**单一出处**——而**单一出处正是让漂移不可能的那件事**。本仓一路在消灭的正是「同一句话写在两个地方」，而消灭它的代价从来都是「多写一处」。

第二条代价：**顺序也是散文。** 描述的段落顺序现在由册子决定，工具文件不再自己排。好处是绑定契约的位置只写一次；代价是册子的作者要想着「模型按什么顺序读」。

第三条代价：**册子是叶子。** 它不 import 本仓的任何模块（只有类型），所以搜索模块与绑定契约模块都改成**从册子里重新导出**它们各自的那句。这是刻意的：册子一旦 import 谁，谁就得小心不 import 回来——而本仓的 import 图里已经有 `dispatch` ↔ `bindings` 那一对环，册子不能再加一条。

## 本篇没有做的事

- **`ROUTES` 区的路本身、常驻索引的渲染、随包详情文件**：#246。本票只建区与类型，并把 `<ptc>` 段的两条路句与截断的两句搬进册子（它们是路表的原料）。
- **八条强制点的完整测试套件**：#247。本票只立了其中一条的守卫（工具的描述 / 指南 / 片段必须是册子的调用）与其直接依赖的三条。
- **参数 schema 的 description 整体搬进册子**：不搬（决定 4 的第 1 条）。只有**两个 schema 之间共享的那一句**搬了，因为它本来就在漂。
- **renderer 里的文字**（子代理的 roster、孩子的追加 prompt、搜索模块的失败文案、任务通知的 XML）：留在原地。它们是 renderer 与活数据的产物，不是工具的声明。
