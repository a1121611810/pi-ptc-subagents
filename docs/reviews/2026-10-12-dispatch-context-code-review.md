## What the axes cleared with evidence

- **Audit 1 complete, no missed call site.** `appendDepthHint` has exactly two production call
  sites, and `promptFileWriter` / `buildArgv` / both `PI_COMMAND` spawns hang off those same two, so
  no path builds a child prompt without the block. The fixture has exactly one consumer.
- **The sentences are true on every path.** Background children get `--session-dir` +
  `--session-id` + `--name` and never `--continue` / `--fork`; the foreground keeps `--no-session`.
  So "you cannot see that session's conversation" holds on both fronts, and "as a fresh context" is
  true for a nested dispatch too. Measured, not argued: a probe at the real spawn seam reported the
  generalist `fulfilled / exit 0 / reportChannel none`, and the named case with the body leading the
  block.
- **The fixture change's blast radius is nil.** The echoed prompt contains the report clause's
  fenced JSON, and the Spec axis checked the one way that could bite: `fencedBlocks` opens only on a
  line-initial fence, and the echo preserves the text verbatim, so no reporter misparse. Measured.
- **No F1–F4 or T1–T4 pattern** in any new assertion; the e2e has no environment gate and runs by
  default.

## What the round did not settle

- **The named-definition case is not covered at the e2e seam.** The content assertion was added to
  the generalist test only; the named case rests on the unit tests plus the shared, unbranched call
  site. A regression that affected only the named path would not be caught end to end.
- **The Spec axis could not run the full suite against a frozen HEAD.** The working tree moved
  underneath its run (this round's own fixes), so "green at HEAD" is inferred from 67 of 68 files
  plus isolated runs rather than one clean whole-suite run.
- Pre-existing and left alone: the other stacked-JSDoc site at `dispatch.ts:1416-1433`, which this
  diff did not touch.
