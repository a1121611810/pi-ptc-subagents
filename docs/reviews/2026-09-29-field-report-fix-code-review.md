## Round 0 — the field finding that changed the design

The batch's headline defect (pitfall #3, "background tasks vanish when the PTC program ends")
was **not** a prompt-surface bug. Root cause, established before any code was written:

- pi 0.87.1 emits `session_start` / `session_shutdown` only at process start, `/new`,
  `/resume`, `/fork`, `/reload`, and exit — never between turns (0.86.1 ≡ 0.87.1 on this
  point; verified by diffing both installed dist trees).
- Background children spawn with `--session-dir <parent's sessionDir>`
  (`dispatch.ts` → `child-process-lifecycle.ts`), so child and parent **share**
  `<sessionDir>/tasks/`. A child's `session_start` therefore ran `reconcileLostTasks()` —
  a directory-wide sweep — over the parent's own records, and its `session_shutdown` sweep
  did the same on exit. Any `pi` process started in the same cwd did the same on boot.

Fix: ADR-0023 task ownership (`ownerPid` / `ownerBootMs` stamped by the registry's spawn
command; startup reconcile reaps only owner-dead or legacy-ownerless records; shutdown reaps
only records this runtime owns).

## The field-count correction (rounds 2-3)

A round-2 finding ("the comment justifies the wrong property") led to a correction that
propagated further than the comment: `TaskRecord` has **21** fields; ADR-0022 §3's code block
lists **19** of them; the other two are ADR-0023's `ownerPid` / `ownerBootMs`. ADR-0022's
"21 fields" heading (and three more mentions) is an authoring miscount that predates this
change. Measured programmatically by three parties (the fixing agent, the orchestrator, and
both round-3 reviewers) because a wrong number in a justification comment is a lie with a
citation. All three reworded sites, the user guide, and the test-file provenance comments were
corrected across 8 files (13 comment-and-title sites, plus one more found by the round-4
reviewers in a file the first sweep missed — see the closing-round section); ADR-0022's body is
deliberately unedited, with the correction carried by its amendment pointer (per ADR-0023's
"amend by reference" boundary).
