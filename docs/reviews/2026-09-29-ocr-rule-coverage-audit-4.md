## 追加:守卫盲点的收紧(本节记录的两条漏网路径,已闭环)

上一节把 file:line 的盲点记为「记录,不修」。这里补上修复,并顺手关掉同形态的第二条。

### C-30 file:line 只认两个解析基准,`render.ts:145` 这种简写静默逃出校验面

- **形态**:`inRepoTarget()` 只按「文档所在目录」与「仓库根」两个基准解析。ADR-0013 §6 补完
  「展开态错误块的两条边界」后新增的 7 处引用写的都是 `render.ts:145` 这种只有 basename 的形态,
  两个基准双双落空 → 引用**静默离开校验面** → 行号漂到 9999 也不会有任何东西变红。
  守卫看上去覆盖了 file:line,实际长期在漏这一整类。
- **处置**:加第三个基准 —— **全仓唯一同名文件**(基于 `git ls-files` 建的 basename 索引)。
  实测 `render.ts` 在全仓唯一(`src/tools/render.ts`),7 处引用第一次真的进入校验面。
  **重名时不接**:本仓只有 `.gitignore` 与 `README.md` 两个重名,猜错会把一条正确引用报成越界,
  那比不校验更糟(会让人去改一条没坏的引用),所以宁可漏不可猜。
  第三条抽成纯函数 `uniqueTrackedMatch()` 单独单测 —— 真实语料打不到歧义分支(两个重名都能被
  更早的基准解析到),不抽出来这条「宁可漏不可猜」就只能靠人读代码确认。
- **逐条核对**(Lead 手工核对 render.ts 每一行,不是照抄 ADR 的说法):
  `78` 八个常量定义段 / `127` `alignRow()` 里「无 meta 直接截断」那条分支(失败行只 push left、
  没有 right,走的正是这条,不是 129/130)/ `145` `firstLine()` 体内 apply `MAX_ERROR_CHARS` /
  `693` `errorText()` 体内 return firstLine / `834` 折叠态 `failed: ${errorText(...)}` /
  `925` 「The failure text is the reason the reader expanded the row at all」注释 /
  `928` 展开态 `?? errorText(result)` 的 fallback / `930` `.slice(0, MAX_LOG_LINES_EXPANDED)`。
  **八条全部属实。**
- **反事实**:把第三条基准改回 `return null` → 基线从 8 条塌回 1 条,且盲点回归测试直接变红
  (`expected null to be .../src/tools/render.ts`)。还原后 19 passed。

### C-31 账本 SHA 断言只认小写十六进制,大写 SHA 静默逃过

- **形态**:`HEX_TOKEN` 字符类是 `[0-9a-f]`,**大写 SHA 整条不进断言三**。将来谁在账本里写个大写
  commit,守卫照样全绿。
- **实测**:8 份账本全扫,**大写形态 0 处** —— 纯理论盲点。
- **处置**:仍然改成 `[0-9a-fA-F]`。**「当前没有」不是纪律**,漏网路径要堵上而不是等它发生;
  git 本身对两种大小写都接受。当前行为零变化(没有大写候选),但逃逸路径没了。

### C-32 账本 SHA 断言用 68 次串行 git spawn,全量并行时稳定超时

- **形态**:断言三对 68 处引用各起一次 `git rev-parse`(去重后 31 个唯一 SHA)。单跑没事,
  47 个测试文件并行时**稳定超过 vitest 的 5 秒默认超时**。
- **为什么这条最坏**:报出来的是 `Test timed out in 5000ms`,而它挂在「账本里的 SHA 无法被 git 解析」
  这条断言下面 —— **红的表面原因与真实原因毫无关系**。timeout 与缺陷长得一样,CI 上随机复现,
  会把人引去查账本。这一条是本轮排查 C-31 时**先撞上、再倒查出**的:我一度以为全量那次失败是 flake,
  抓到输出文件才发现是超时,不是 SHA。
- **处置**:改用 `git cat-file --batch-check` **一次调用判定全部**(先去重)。实测 20 次串行 spawn =
  0.263 秒,单次 batch-check = 0.011 秒。68 次变 1 次,超时面直接消失。
- **配套**:优化最容易出的错是「快了但判得不一样」,所以加了一条测试把批量路径与单条路径钉在一起
  (真实语料全 resolves、混入不存在的 SHA 必须标 missing、重复传入同一 SHA 不得影响判定),
  以及一条「输出行数与输入对不齐就当作环境问题重试、绝不硬把某一行安到某个 SHA 上」的防御。
- **验证**:全量连跑两次均绿(797 -> 798 passed),不再出现 timeout。

### 同类排查:符号断言那侧没有同形态问题

`EXTERNAL_VOCABULARY` 是显式清单(名字 + 理由)并配两条反向守护(真进了 src/ 就红、文档不再提也红),
其余跳过路径(`SYMBOL_SHAPES` 形状、`HEX_SHA_LIKE`、`PACKAGE_KEYS`、与仓库根路径同名的 token)
每一条都有注释写明理由。**没有「静默离开校验面」的同类漏网。**
