# 上网查资料 · 读文档（web_ds_search · doc_ds_ocr）

pi 面上，搜索能力**只活在被派出的子代理里**（父会话不注册这个工具）——「这条来源靠不靠谱」的判断力在干活的子代理侧。

> Kimi 面（`ptc-tools` 插件）例外：`web_ds_search` 模型可直接调用，配额按 MCP server
> 进程计（默认 30 次），DeepSeek key 走 env → Kimi Code `config.toml` 两级解析。

三动作：

- `search({ query, count? })`：概览（title/url/snippet，默认 10 条）。snippet 是 DeepSeek 自算的短摘要——便宜且不丢事实；长 summary 不经概览给
- `open({ url })`：抓整页（记忆命中最近结果则免费）
- `find({ url, pattern })`：页内按正则匹配行（先查记忆）

预算与配额：

- 模型可见文本预算 12,000 字符；超了按排名**整条丢弃** + 告知丢了哪些（要哪个用 open 补抓）——不按字符截断
- 配额每进程计（`searchMaxCalls`，默认 30 次/进程，0 = 不限；只计成功调用）
- 开关 `webDsSearch`（`~/.pi/agent/ptc.json`）是布尔，**默认关**：开关关 = 工具不存在；开关开但缺凭据 = 注册但调用返回可读错误

- **开关关着就别派这类任务，也别去改它**：那是用户的配置，不是你的开关——改了等于替用户开了一个有网络出口、按次计费的能力。直接说明「搜索没开，做不到」；用户要的话他会自己开。实测（2026-11-01）：读到「默认关」后去改配置、翻源码找开关位置的会话，比老老实实说做不到的慢 4 倍

## 读文档（doc_ds_ocr · 文档域）

本地 PDF / Word / PPT / 图片转文字——同一套 DeepSeek 通道的第二个能力（官方 2026-11-13 开放的 OCR 接口）。

- pi 面上它和搜索一样**只活在子代理里**：父会话不注册，孩子才有
- Kimi 面是第三件 MCP 工具：`doc_ds_ocr({ path, workdir })`
- **文件会离开本机**——上传到 DeepSeek 侧处理，本机不留副本；只允许工作区（Kimi 面是 `workdir`）内的文件
- 逐页返回；同一份文件重复识别不重复计费（记忆命中）
- 配额与搜索**共用**同一份（`searchMaxCalls`，进程级总护栏）
- 开关 `webDsOcr` **独立**于 `webDsSearch`，**默认关**——它把文件发出去，性质比发关键词更敏感，能单独关
- 模型可见预算 12,000 字符：超了**整页丢弃** + 告知省略了哪些（官方按整份文件解析，不支持只识别指定页）
- 孩子跑 DeepSeek 模型且已开服务端搜索时，**用本仓的搜索工具即可，别两套一起用**（重复检索 + 重复计费）
