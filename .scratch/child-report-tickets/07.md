## What to build

The release artifact agrees with the code, and the documentation tells the truth.

Adding a registered tool breaks the distribution gate, which pins the exact expected set of tools. That pin exists because a previous feature passed several review rounds and a green suite while the release artifact still asserted the old count. It is updated as part of this work, not after it.

The user-facing documentation gains the child report: what it carries, how a caller reads it, what it costs to produce, and how to opt an agent out.

## Acceptance criteria

- [ ] The distribution gate's expected tool set includes the report tool, and the gate passes on the built artifact
- [ ] The gate is run against a real build, not reasoned about
- [ ] The README describes the child report and where a caller reads it
- [ ] The background-dispatch usage guide describes the report on a background task
- [ ] The documentation states how an agent opts out
- [ ] The full release gate passes: typecheck, lint, format check, build, tests, and the distribution verification
