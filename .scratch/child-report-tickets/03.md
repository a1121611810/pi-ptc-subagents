## What to build

The reliable channel: a child hands its report back through a declared tool rather than through prose.

The extension registers a report tool with a declared output schema. The host activates it in the child, and reads its structured payload off the child's tool-execution event. When that channel fires, it wins over the prompt channel — it is JSON produced against a declared shape, not scraped text.

The activation is the delicate part. The child only receives a tool-list flag when its agent markdown declares tools of its own, so a child whose agent declares none would receive no tool flag at all and the tool would sit inactive with no error anywhere. Merging the report tool into the child's tool list is load-bearing, and it is exactly the kind of change that reads as correct and does nothing.

The tool's description, snippet and guidelines become the single home of the contract. The prompt clause from the previous ticket shrinks to one sentence requiring the child to call it.

## Acceptance criteria

- [ ] A report tool is declared with an output schema, and the shape it accepts matches the shape the host validates
- [ ] The tool is activated in a dispatched child even when the agent's own markdown declares no tools at all
- [ ] The host reads the report from the child's tool-execution event when the child calls the tool
- [ ] A report delivered by the tool wins over a report delivered by the prompt channel in the same transcript
- [ ] The contract text lives in the tool's own description, and the prompt clause no longer restates the shape
- [ ] The tool is not active in the parent's ordinary surface
- [ ] A transcript where the tool channel never fires still yields a report via the prompt channel
