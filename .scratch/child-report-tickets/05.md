## What to build

The model reads a child report the same way every time.

On the subagent surface there is no code-mode runtime, so the tool's structured channel reaches nobody. The report therefore has to be rendered into the text the model actually reads, as a fixed shape: summary, then findings, then files, then usage. The child's own prose follows the rendered block, so the model sees the conclusion first and the reasoning second.

The declared output schema gains the report alongside what it already carries, so a caller that can read a structured channel gets the same value the model sees rendered.

## Acceptance criteria

- [ ] The tool-result text contains the summary, every finding with its evidence, the file list and the usage, in a fixed order
- [ ] The child's own prose survives, placed after the rendered report
- [ ] A missing report is visibly marked in the text rather than appearing as an empty section
- [ ] The declared output schema carries the report for callers that read a structured channel, and the schema matches what the renderer emits
- [ ] The rendered shape is bounded — a child returning a large report does not produce unbounded tool-result text
- [ ] Rendering follows this repo's existing value-tree conventions rather than inventing a new shape
