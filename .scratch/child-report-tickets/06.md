## What to build

A background child's report is as inspectable as a foreground child's.

Background dispatch returns a handle, not a result, so the report has nowhere to land until the child finishes. The report must survive into the task's persisted output, readable through the existing task-inspection path, exactly as the child's text already does.

Without this, background children — the ones doing the long surveys — are the only children whose answers stay prose.

## Acceptance criteria

- [ ] A background child's report is persisted with its output and is readable after it finishes
- [ ] The persisted channel value says which channel delivered it, matching the foreground behaviour
- [ ] A background child that ignored the contract is marked as having ignored it, in the persisted output
- [ ] A still-running task has no report, rather than an empty one
- [ ] A failed background child carries no report rather than an empty one
