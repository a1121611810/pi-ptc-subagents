## What to build

A child that ignores the contract is reported as having ignored it.

This is the behaviour that keeps the whole feature honest. Under the contract, a child that returns prose and nothing else is a **reachable, ordinary** outcome — it forgot, it ran out of room, it wrote malformed JSON. The result must say so in a field that is always present, so a caller can tell "no report" from "a report with nothing in it".

The child still resolves as fulfilled, with its prose intact. Discarding a completed child's answer because it was formatted badly is worse than handing the answer over marked as untrusted.

Nothing here is a fallback that quietly produces a plausible-looking answer. The channel value is the whole message.

## Acceptance criteria

- [ ] The channel field is always present on the result, including when no report arrived
- [ ] A child that returns prose only under the contract resolves fulfilled, keeps its prose, and states that no report arrived
- [ ] A child whose report block is malformed is treated the same way as one that omitted it, and the two are distinguishable in the result if they differ
- [ ] An implementation that silently returned the prose as though it were a report turns the suite red
- [ ] A refused dispatch — depth, concurrency, unknown agent, spawn failure — carries no report rather than an empty one
- [ ] The agent frontmatter opt-out is honoured: an opted-out agent is never asked for a report and is never marked for failing to give one
- [ ] The opt-out defaults to on, so an agent that says nothing gets the contract
