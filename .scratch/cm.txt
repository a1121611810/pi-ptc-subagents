docs: ADR-0031's open-source claims were never executed; measured and marked

The 1.5.0 release carried two claims that had been written as decisions in an
earlier session, recorded as facts, and then shipped inside the tarball
because CHANGELOG.md is in `files`:

- "The repository is public, and main is writable only by the maintainer ...
  Release authority is enforced by a refs/tags/v* ruleset". The repository is
  still private, and no ruleset exists: the endpoint returns 403 with GitHub's
  own "Upgrade to GitHub Pro or make this repository public to enable this
  feature". 1.5.0 merged to main and pushed its tag with no rule object having
  evaluated either — the tag was a plain capability check.
- "The next version published from here carries an npm provenance attestation".
  It does not, and never has: dist.attestations is empty for every published
  version from 1.1.1 through 1.5.0. Provenance needs a public source repo, so
  the precondition never held and ADR-0018 §7 was never falsified.

The decision to open-source is unchanged and still right; only its execution is
missing. Both ADRs now carry the measurement rather than the intent, so the
next reader gets told what IS true instead of what was planned.

The OIDC mechanism is not implicated — 1.5.0's log reads "oidc Successfully
retrieved and set token", PUT 202, "+ pi-ptc-subagents@1.5.0". Trusted
publishing worked; what was missing is its precondition.

Note what none of this repo's gates could catch: every one of them checks the
SHAPE of a claim — that a file:line resolves, that a constant matches a rule —
and none reads prose to ask whether the thing it describes still exists. Five
review rounds and a green release gate all passed these claims. That is the
gap docs/testing-constraints.md records, and this release is a clean instance
of it.
